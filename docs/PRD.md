## 1. Summary

PlexusTerm is a terminal and remote-session manager with a built-in AI assistant: local shells, SSH, SFTP, tunnels, serial, Telnet and Mosh in one window, aimed at sysadmins, DevOps and network engineers, plus developers who run AI CLI tools.

**PlexusTerm Native** rebuilds it as a fully native desktop application — **no webview, no HTML/CSS/JS runtime**, Rust end to end on GPUI — with **100% functional parity** and the **same visual identity**. The UI is GPU-rendered and the terminal is emulated in-process.

## 2. Problem

The Tauri version works, but the webview is the bottleneck and the main source of platform bugs:

- On Linux the shipped default (DOM renderer) measures ≈11 ms per key but cannot keep full-screen redraws (AI CLIs, `htop`) smooth; the GPU path that fixes smoothness costs 50–70 ms per key under WebKitGTK and is therefore off by default (UG:351). Users must choose between latency and smoothness.
- NVIDIA needs DMABUF environment workarounds (`webkit_env_in`, `SR/platform.rs:40-58`, Linux only).
- WebKitGTK blocks `navigator.clipboard`, forcing a plugin round-trip.
- Every byte of terminal output crosses an IPC boundary (Rust → Channel → JS → xterm.js), requiring a coalescer (8 ms burst / 4 ms window / 64 KB, `SR/terminal/coalesce.rs:16-20`).
- Two languages, two test stacks, two dependency trees (1306 Vitest cases in 137 files + 508 Rust tests: 1814 tests, §11.1).

## 3. Goals

1. **G1 — Parity.** Every requirement in §7 behaves as in v0.2.15. Parity is the acceptance bar, tracked by the parity matrix (§11.1); no feature is dropped silently. Every deliberate difference is listed in §4.1; anything not listed there must match v0.2.15.
2. **G2 — Same aesthetics.** Same token model, typography, spacing, radii, states and layout (§8). A v0.2.15 user recognizes the app immediately.
3. **G3 — Performance.** Low latency *and* smooth full-screen redraws at the same time, GPU on by default on every platform (targets and method in §10).
4. **G4 — Data compatibility.** Reads and writes the existing config directory, files and keyring entries unchanged; native-only files (DATA-1, §4.1) are additive and ignored by v0.2.15; in-place upgrade with zero migration steps; v0.2.15 remains a rollback (§9).
5. **G5 — One language.** Rust end to end; one test runner (`cargo test`).

## 4. Non-goals

- New features beyond v0.2.15 (command palette, tab/layout restore, multi-window tab drag, config hot-reload, macOS packages) — §15 backlog. Deliberate deviations are enumerated exhaustively in §4.1; anything not listed there must match v0.2.15.
- Changing config formats, file `version` numbers, keyring names or session schemas.
- Rewriting protocol logic that already works in Rust (SSH, SFTP, tunnels, telnet, serial, mosh, keygen, AI clients): it is **reused**.
- Pixel-perfect reproduction of browser rendering (subpixel CSS antialiasing). Visual parity is judged by tokens and the §8.7 checklist.
- macOS CI, Metal-based visual tests, LSP in the viewer, telemetry beyond opt-in local logs.

## 6. Architecture

### 6.1 Principles and structure

Hexagonal architecture with a screaming structure: crates named after the domain, not the framework.

```
crates/
  core-domain/        sessions, tunnels, macros, settings, history, shortcuts (pure types + rules)
  core-storage/       atomic 0600 JSON persistence, keyring adapter (ported from SR/storage.rs, secrets.rs)
  proto-pty/          portable-pty, shell detection, shell integration (Windows OSC 9;9)
  proto-ssh/          russh client, known_hosts, jump hosts, remote cwd
  proto-sftp/         russh-sftp, edit-and-reupload watcher
  proto-serial/       serialport
  proto-telnet/       NAWS / TERMINAL-TYPE / ECHO / SGA
  proto-mosh/         mosh-server bootstrap + mosh-client in PTY
  tunnels/            -L / -R / -D SOCKS5
  ai/                 providers, limiter, text caps
  tools/              keygen (+PPK), port/network scan, WoL, remote monitor, git (read-only)
  term-engine/        alacritty_terminal wrapper: grid, scrollback, selection, search, OSC handlers, line tracker
  ui-theme/           token derivation (§8), schemes, fonts
  ui-kit/             widgets (own or gpui-kit, D4)
  app/                windows, panes, features wiring, runtime bridge (binary)
```

- **Ports** (traits) live in `core-domain`; adapters live in `core-storage`, `proto-*`, `ai`, `tools`. Only `ui-*` and `app` depend on GPUI.
- **Container-presentational in GPUI:** feature state lives in `Entity<T>` models (containers) that call application services; `Render` views are presentational and read only model state and theme tokens.
- The Tauri commands (`SR/lib.rs:687-809`) become **application service methods**; the events (`tunnel-status`, `sftp-edit-saved`, `open-workspace` and the sharing events of §7.10) become typed internal messages. No IPC serialization.
- **Runtime bridge:** GPUI schedules work on its own executors (`BackgroundExecutor` / `ForegroundExecutor`), not Tokio. Protocol crates (russh, russh-sftp, reqwest, tunnels) run on one dedicated multi-thread Tokio runtime held as a GPUI `Global`, following Zed's `gpui_tokio` crate (Apache-2.0; vendored into `app/runtime.rs` with its notice). Services expose `Tokio::spawn(cx, fut) -> Task<_>`; results reach models via `cx.spawn` / `entity.update`. No Tokio call ever runs on the GPUI main thread (enforced with `clippy::disallowed_methods` outside the bridge).
- **Terminal widget:** one `alacritty_terminal::Term` per pane owned by a model; PTY reader on a background thread feeds the parser; the view paints only damaged lines through GPUI's text system and glyph atlas, at most one redraw per frame. Terminal and inputs implement GPUI `EntityInputHandler` so IME preedit renders at the caret.

### 6.3 Terminal stability and performance architecture

The terminal must be fast **and** never take the app down. These rules are binding for every session kind (local, SSH, Mosh, Telnet, serial, shared).

**Threading and data flow (per session)**

```
source (PTY reader thread | Tokio SSH/telnet task | serial thread)
   └─► bounded byte ring (4 MiB) ──► parser thread: alacritty_terminal::Term under FairMutex
                                        └─► dirty flag + damage ─► UI thread (vsync): snapshot damaged lines, paint
UI input ─► bounded write queue ─► writer thread/task ─► source
```

- **ST-1 Parser off the UI thread.** Each session has its own parser thread that owns parsing into `Term`. The UI thread never parses bytes and never does I/O.
- **ST-2 Short, fair locks.** The parser parses in slices of at most 1 MiB or 4 ms, then releases the `FairMutex`; the UI holds the lock only to copy damaged lines into a render snapshot, never while painting or shaping.
- **ST-3 Backpressure, never drops, never unbounded.** Every queue is bounded. A full byte ring stops reading from the source: PTY reads block naturally; SSH stops consuming the channel so the SSH window closes (protocol flow control); serial/telnet stop reading the socket. Output is never discarded and memory never grows with output speed.
- **ST-4 Latest-frame rendering.** The UI paints only when the dirty flag is set, at most once per vsync, from the latest state; intermediate states are skipped, never queued. During floods the parser keeps up and the UI shows the newest screen.
- **ST-5 Non-blocking input.** Keystrokes and pastes go to a bounded per-session write queue drained by a writer thread/task; large pastes are chunked (64 KiB) and keep order; the UI never blocks on a full PTY or slow network.
- **ST-6 Resize coalescing.** Resizes apply to `Term` and the PTY/SSH/telnet NAWS at most once per frame, last size wins.
- **ST-7 Fast first prompt.** The shell PTY is spawned in parallel with window creation; schemes, grammars and non-default fonts load lazily.

**Fault isolation**

- **ST-8 One session crash never kills the app.** Release profile uses `panic = "unwind"` (v0.2.15 uses `abort`). Every session thread/task runs behind a supervisor (`catch_unwind` / joined `JoinHandle`): on panic or I/O error the supervisor ends the backend session and the pane behaves exactly as v0.2.15 does when that session kind ends (`ST/features/terminal/TerminalView.tsx:457-463,524-533,545-559`, `EN/terminal.ts:41-43`): the error is written into the pane in red (as a failed SSH or serial connection is), then a local, SSH, Telnet or shared pane closes (TERM-19), a serial pane keeps the pane open with `[Session ended. Close this tab or open the port again.]` (SER-1) and a Mosh pane keeps `[mosh-client exited. Close this tab or open the session again.]` / `[mosh-client exited with code {code}. Close this tab or open the session again.]` (MOSH-1); no new message or button is introduced. The failure is logged (NFR-11) and a minidump is written (native-only, never shown in the UI, §4.1 row 8); other panes and tabs continue.
- **ST-9 Bounded parser state.** Caps on every attacker-controlled input: OSC/DCS payload 64 KiB, title 4 KiB, OSC 8 URI 8 KiB, hyperlinks per screen 10 000, scrollback 10 000 lines (ring buffer), images not supported. Over-limit sequences are dropped, never buffered.
- **ST-10 GPU device loss.** Lost device/surface → the renderer is recreated; if it cannot be recreated the app switches to the software path (NFR-10) without losing session state, as v0.2.15 switches to the DOM renderer on a lost WebGL context (UG:351). Native-only, no UI: the recreate-before-fallback attempt (at most 3 in 60 s) is an implementation policy.
- **ST-11 UI hang watchdog.** A frame longer than 250 ms logs a warning with the active view; longer than 2 s captures a main-thread backtrace to the log. Debug builds enable `parking_lot` deadlock detection.

**Code rules (CI-enforced)**

- **ST-12** `clippy::unwrap_used`, `expect_used`, `panic`, `indexing_slicing`, `await_holding_lock` denied outside tests; `#![forbid(unsafe_code)]` in every crate except the narrow platform shims that need it, each `unsafe` block documented.
- **ST-13** `Cargo.lock` committed, exact pins for GPUI and `alacritty_terminal`, MSRV declared; dependency upgrades are their own work units with the full soak run.
- **ST-14 Allocator.** `mimalloc` adopted only if M0 shows ≥ 10% on NFR-2 without RSS regression; otherwise the system allocator.

**Stability verification**

- **ST-15 Soak test (nightly, 8 h; release, 24 h):** 30 tabs / 60 panes mixing local shells, SSH to a Docker sshd and a flood generator (`yes`, random SGR/OSC/UTF-8 streams, `vtebench`), resize storms, tab open/close churn, SSH disconnect/reconnect loops. Pass: 0 crashes, 0 hangs > 2 s, RSS growth ≤ 5% after the first hour, no file-descriptor or thread leak.
- **ST-16 Fault injection:** PTY EOF mid-write, child killed with SIGKILL, SSH TCP reset, serial unplug, GPU device loss simulation, full disk on log/save; each ends only its pane, following ST-8.
- **ST-17 Fuzzing** of the VT feed path (`Term` + our OSC handlers) in addition to §11.2 targets; parser fuzz runs ≥ 1 h per release.

- **SHARE-15** Privacy and keys, per the protocol crate at `RL` HEAD `5606b70` (`RL/crates/protocol/src/{keys,noise,frame,link}.rs`, `RL/docs/protocol.md`, `RL/docs/security.md`; the pinned rev `5b330608` is re-checked in M0, O6). Every link carries a 32-byte random `secret` (one per access: View only, Can type) and a per-share 16-byte random `share_id`; a third 32-byte `owner_secret` never leaves the sharer. From each secret HKDF-SHA-256 with salt `plexusterm-share v1` derives `link_id` (16 bytes, info `link id`, relay-visible), the Noise PSK (32 bytes, `handshake psk`) and `relay_auth` (32 bytes, `relay auth`); the relay stores only `verifier = SHA-256(relay_auth)` and a joining party proves knowledge with `HMAC-SHA-256(verifier, "plexusterm-share v1 proof" ‖ role ‖ share_id ‖ challenge)` over a fresh 32-byte relay challenge (`role` 1 viewer, 2 owner, so a viewer proof never replays as an owner proof). Each admitted viewer runs its own `Noise_NNpsk0_25519_AESGCM_SHA256` handshake with the sharer (viewer = initiator, PSK = the link's handshake key, prologue `plexusterm-share v1` ‖ `share_id`, fresh X25519 ephemerals on both sides → forward secrecy); message 1 carries `{client, resume_from}`, message 2 `{access, cols, rows}` and is sent only after the sharer approves, and the access a viewer gets follows from the PSK it completed the handshake with, never from the `link_id` the relay reported. After the handshake the raw Noise split gives one AES-256-GCM key per direction; frames are `0x02 ‖ seq (u64) ‖ AES-256-GCM(key, nonce = 0x00000000 ‖ seq, aad = "PTS1" ‖ share_id ‖ viewer_id ‖ direction ‖ seq, plaintext ≤ 32 KiB)`, `seq` starting at 1 per key; a receiver drops any frame whose `seq` is not strictly greater than the last authenticated one, so the relay (which forwards opaque bytes, keeps state in memory only and holds no key) can neither read, move, replay nor inject frames. Disconnect sends `rotate {link_id, new}` before `kick`, so the old secret stops working and the new links are shown (SHARE-3). The secret lives only in the URL fragment (`https://<viewer-origin>/s/<share-id>#<secret>`, SHARE-2); the viewer page removes it from the address bar and needs HTTPS (Web Crypto); a link without its fragment is "incomplete", not wrong (SHARE-13). A browser viewer still trusts the viewer page's server (SHARE-3 note). Primitives come from `snow` 0.10, `aes-gcm` 0.10, `hkdf` 0.12, `hmac` 0.12, `sha2` 0.10 with constant-time proof checks (`subtle`), all MIT/Apache-2.0 under the crates' MIT licence (§6.2). Secrets and session keys are `Debug`-redacted and operational logs carry only a 6-byte hash of `share_id` (`ShareId::log_tag`). Local HEAD also defines `plexusterm://s/<relay-host>/<share-id>#<secret>` deep links and `<viewer-origin>/relay.txt`; v0.2.15 opens only pasted `https://` links and reads `<meta name="plexusterm-relay">` (SHARE-13), and native 1.0 keeps that behaviour — whether the pinned rev already ships deep links is part of the M0 check (`SR/share/mod.rs:395-404,449`, `SR/share/host.rs:360-367`, `SR/share/watch.rs:208-209`, UG:292). *Native test plan:* the crates' own tests (`derivation_is_deterministic_and_separates_outputs`, `proof_checks_only_with_matching_inputs`, `both_sides_derive_the_same_distinct_keys`, `wrong_psk_or_share_is_rejected`, `payload_is_not_visible_in_handshake_bytes`, the frame replay tests and `RL/crates/protocol/tests/vectors.rs`) run in the native CI against the pinned rev; PlexusTerm-side rows stay under SHARE-2/3/9/13.

## 9. Data and compatibility

- **DATA-1** Config directory resolved exactly as Tauri's `app_config_dir` for `dev.plexusterm.app`: Linux `$XDG_CONFIG_HOME/dev.plexusterm.app` (default `~/.config/dev.plexusterm.app`); Windows `%APPDATA%\dev.plexusterm.app` (Roaming). Never the `ProjectDirs` convention. Files: `sessions.json`, `tunnels.json`, `settings.json`, `macros.json`, `history.json`, `ai-chats.json`, `opencode-go-models.json` (cache), `share-audit.log` (JSON lines, 30 days, SHARE-11), `shares/share-<pid>-<id>.json` (crash markers, SHARE-12), and the native-only `recent.json` (DATA-6). No v0.2.15 log file lives there: its only diagnostic output is the latency log under `$PLEXUS_LATENCY_LOG` (TERM-17, `SR/diag.rs:9-13`). Per-project `<project>/.plexusterm/settings.json` follows DATA-1b (0644, not private).
- **DATA-1a** Schemas verbatim from v0.2.15: `sessions.json` `{version:1, folders, sessions}`; `tunnels.json` `{version:1, tunnels}`; `macros.json` `{version:1, macros}`; `history.json` `{version:1, hosts}`; `ai-chats.json` `{version:1, chats}` (unknown entries preserved); `settings.json` `{version:2, …}`. ### 10.1 Security model (NFR-6)

v0.2.15's boundary came from Tauri capabilities (opener, dialog open/save, clipboard text, notifications) and a CSP (`connect-src ipc:` only). Natively the trust boundary moves to the VT parser, protocol inputs and widgets:

- **SEC-a** Terminal: OSC 52 clipboard write and read are not supported (as in v0.2.15, which ships no clipboard addon, `package.json:33-38`); the sequence is consumed and ignored; titles (OSC 0/2) stripped of C0/C1 and capped; OSC 8 and detected links only `http`/`https`/`mailto` (plus `file://` as files in local panes, TERM-14), opened on Ctrl+click without a confirmation step, never passed to a shell; pastes go through the multi-line confirmation with ESC and bracketed-paste terminators removed.
- **SEC-b** Markdown: inline HTML sanitised as in VIEW-3 (scripts, event handlers, `javascript:` links, frames, forms, styles removed); images per VIEW-3a: local/SFTP image files ≤ 20 MiB from the file's own machine, `https:` and `data:image/` sources fetched when the preview opens, `http:` and every other scheme dropped, image paths never trusted as paths; links through the same allow-list.
- **SEC-c** AI HTTP: rustls, `redirect::Policy::none()`, keys only from the keyring, zeroized after use; terminal output never sent (AI-7, AI-9).
- **SEC-d** Update check: GET `api.github.com/repos/jorgealonsodev/PlexusTerm/releases/latest` over rustls with the v0.2.15 client settings (user agent, 15 s / 5 s timeouts, reqwest's default redirect policy, `SR/updates.rs:66-72`); notice only — never downloads or executes (UI-6).
- **SEC-e** SFTP edit copies: per-session temp dir `plexusterm-sftp-*`, 0700 on Unix, removed when the session drops.
- **SEC-f** SSH: known_hosts policy of SSH-2; secrets in keyring only (DATA-3).
- **SEC-g** Files: private files 0600 (DATA-2); the per-project `.plexusterm/settings.json` is deliberately 0644 (DATA-1b).
- **SEC-h** Remote strings: nothing from a remote (terminal output, SFTP names, git output, AI replies) reaches a command line, URL opener or file path without validation; size caps kept.
- **SEC-i** Supply chain: `cargo deny` (licenses, advisories, duplicates) and `cargo audit` in CI.
- **SEC-j** Sharing: relay token in keyring only; relay/viewer URLs scheme-checked (TLS except localhost); Can type is a remote shell and is labelled so, with `sudo -k` on start by default; every join is notified and logged; viewer input goes through the hold rules and the session's own write path, never multi-exec, macros or history; links carry the secret only in the fragment and the relay stores only SHA-256 verifiers; each viewer gets its own Noise `NNpsk0` handshake and AES-256-GCM keys with sequence-bound AAD, so the relay can neither read, replay nor inject frames; Disconnect rotates the link before kicking; shares expire ≤ 12 h; the viewer page fetch and `build.txt` fetch follow no redirects and cap body size (SHARE-1, 5, 8, 13, 15).
- **SEC-k** Watched shares: a shared pane is an untrusted VT sink: query answers, OSC 52, titles, notifications, links, logging and AI are disabled for it (SHARE-14).

### 12.3 Beta channel, coexistence and rollback

Native-only delivery channel (§4.1 row 9): beta builds install as `plexusterm-beta` (distinct package, binary and desktop entry, no `.code-workspace` association) but share the config directory; both apps may run concurrently under DATA-2a. ## 19. Glossary

- **Parity:** behavior identical to v0.2.15 for a requirement, verified by its matrix row.
- **Disposition:** how a v0.2.15 test is carried over (`ported`, `ui`, `manual`, `dropped`).
- **DEV mode:** tab state for AI CLI tools (right column, tree explorer, git bar).
- **Multi-exec:** broadcasting input to every pane.
- **Tier-1 latency:** in-app `key_received → frame_submitted`.
- **End-to-end latency:** key press to photons, measured externally.
- **View-model:** GPUI `Entity<T>` holding feature state; views only render it.
- **Port / adapter:** domain trait / its infrastructure implementation.
